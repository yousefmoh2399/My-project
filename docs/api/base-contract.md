# BASE & BUILDING SERVER CONTRACT SPECIFICATION

**Protocol Version:** 1.0.0 (Phase 05)  
**Endpoint Target:** Nakama Server Runtime (Go / TypeScript RPCs)  
**Persistence:** PostgreSQL (`player_base_buildings`, `base_upgrade_operations`)  
**Client Status:** Non-authoritative presentation & simulation

---

## 1. ARCHITECTURAL & SECURITY PRINCIPLES

1. **Untrusted Client:** The Unity mobile client is untrusted. All building levels, upgrade prerequisites, resource deductions, construction durations, and upgrade completions are validated and persisted server-side.
2. **No Direct Database Access:** The client interacts exclusively through authenticated Nakama RPCs. No direct connections to PostgreSQL (port 5432) are permitted.
3. **Idempotency & Double-Spend Protection:** All state-mutating requests (`base.upgrade.request`, `base.upgrade.cancel`) require client-generated UUIDv4 `idempotency_key` headers. If a duplicate request is received, the server returns the cached result without re-deducting resources or restarting timers.
4. **Server-Authoritative Clock:** Construction and upgrade progress is tracked using UTC timestamps generated by the server (`started_at_server`, `completes_at_server`). The client uses these timestamps solely to calculate local UI progress bars. Local device clock changes cannot accelerate timers.

## 2. API ENDPOINTS & DTO CONTRACTS

### 2.1 `base.get` (Fetch Player Base State)
Retrieves the player's current base layout, building levels, and active upgrade operations.

- **RPC Method:** `kww.base.get`
- **Authentication:** Bearer Session Token (Nakama Auth)

#### Request Payload:
```json
{}
```

#### Response Payload (`200 OK`):
```json
{
  "grid": {
    "width": 20,
    "height": 20,
    "cell_size_meters": 4.0
  },
  "buildings": [
    {
      "building_id": "bld_hq",
      "type": "CommandCenter",
      "current_level": 1,
      "grid_x": 8,
      "grid_y": 8,
      "footprint_width": 4,
      "footprint_height": 4,
      "is_upgrading": false,
      "upgrade_op": null
    },
    {
      "building_id": "bld_tank_factory_01",
      "type": "TankFactory",
      "current_level": 1,
      "grid_x": 13,
      "grid_y": 13,
      "footprint_width": 4,
      "footprint_height": 3,
      "is_upgrading": true,
      "upgrade_op": {
        "operation_id": "op_bld_upg_982341",

}
```

### 2.2 `base.upgrade.request` (Commence Structure Upgrade)
Validates building prerequisites, verifies player resource balance, deducts resources in a PostgreSQL transaction, and starts the server-authoritative upgrade timer.

- **RPC Method:** `kww.base.upgrade.request`
- **Authentication:** Bearer Session Token (Nakama Auth)

#### Request Payload:
```json
{
  "building_id": "bld_tank_factory_01",
  "expected_current_level": 1,
  "idempotency_key": "c3f851da-45d2-430b-9366-2679dc6e8f12"
}
```

#### Response Payload (`200 OK`):
```json
{
  "success": true,
  "building_id": "bld_tank_factory_01",
  "current_level": 1,
  "target_level": 2,
  "operation": {
    "operation_id": "op_bld_upg_982341",
    "started_at_server": "2026-11-19T13:00:00Z",
    "completes_at_server": "2026-11-19T13:01:00Z",
    "total_duration_seconds": 60
  },
  "remaining_resources": {
    "gold": 45000,
    "oil": 19500,
    "iron": 12100
  },
  "server_timestamp_utc": "2026-11-19T13:00:00Z"
}
```

### 2.3 `base.upgrade.cancel` (Abort Upgrade in Progress)
Aborts an in-progress construction operation, terminates the server timer, and refunds partial or total resources per configuration.

- **RPC Method:** `kww.base.upgrade.cancel`
- **Authentication:** Bearer Session Token (Nakama Auth)

#### Request Payload:
```json
{
  "building_id": "bld_tank_factory_01",
  "idempotency_key": "7e14a22b-b6d1-4cb5-8271-bf17e7d56e91"
}
```

#### Response Payload (`200 OK`):
```json
{
  "success": true,
  "building_id": "bld_tank_factory_01",
  "current_level": 1,
  "is_upgrading": false,
  "refunded_resources": {
    "gold": 1000,
    "oil": 500,
    "iron": 400
  },
  "server_timestamp_utc": "2026-11-19T13:00:30Z"
}
```

---

### 2.4 `base.upgrade.sync` (Sync Completed Upgrades)
Polls or acknowledges upgrade completion. When `server_timestamp_utc >= completes_at_server`, the server increments `current_level` in the database, removes the operation record, and emits an event.

- **RPC Method:** `kww.base.upgrade.sync`
- **Authentication:** Bearer Session Token (Nakama Auth)

#### Request Payload:
```json
{
  "building_id": "bld_tank_factory_01",
  "idempotency_key": "9d41b6c0-639a-4e2b-bbd0-08f3315a6bfa"
}
```

#### Response Payload (`200 OK`):
```json
{
  "building_id": "bld_tank_factory_01",
  "new_level": 2,
  "is_completed": true,
  "server_timestamp_utc": "2026-11-19T13:01:05Z"
}
```

## 3. FIELD TRUST & CLIENT DISPLAY CLASSIFICATION

| Field | Source of Truth | Client Treatment | Security Vulnerability If Trusted From Client |
|---|---|---|---|
| `building_id` | Client (Target ID) | Sent in request | Spoofing another player's base structure; validated against auth context. |
| `expected_current_level` | Client (Guard) | Optimistic concurrency check | Server rejects if database level does not match. Prevents race conditions. |
| `current_level` | **Server Authoritative** | **Display Only** | Client cannot set building level; arbitrary level hacking. |
| `upgrade_cost` | **Server Authoritative** | **Display Only** | Client could reduce upgrade costs to 0 gold/oil/iron. |
| `started_at_server` | **Server Authoritative** | Display & UI interpolation | Speed hacking if client-provided. |
| `completes_at_server` | **Server Authoritative** | Progress bar normalization | Clock alteration to bypass upgrade wait times. |
| `idempotency_key` | Client Generated | Session deduplication key | Duplicate requests grant multiple levels or double-deduct currency. |

## 4. ERROR CODES CATALOG

| HTTP / Code | Error Key | Description | Remediation |
|---|---|---|---|
| `400` | `BUILDING_NOT_FOUND` | Specified `building_id` does not exist in player's base. | Refresh base state via `base.get`. |
| `400` | `PREREQUISITE_NOT_MET` | Command Center level is below required prerequisite for target tier. | Upgrade Command Center first. |
| `400` | `INSUFFICIENT_RESOURCES` | Player wallet has inadequate Gold, Oil, or Iron. | Gather or produce required resources. |
| `409` | `BUILDING_ALREADY_UPGRADING` | Building currently has an active construction operation. | Await completion or cancel existing operation. |
| `400` | `BUILDING_MAX_LEVEL` | Structure is already at maximum level cap (Level 10). | Cannot upgrade beyond maximum level. |
| `200` | `IDEMPOTENT_REPLAY` | Operation with identical `idempotency_key` was previously processed. | Returns original response without side effects. |
